# 04 - Update docs after implementation

For **[ISSUE / MERGE REQUEST]**, review the approved business intent, the merged or proposed code diff, relevant tests, and verification results. Read `docs/README.md` and the docs related to the changed behavior.

Update only the current docs that no longer describe the agreed product behavior or current technical solution. Business docs must reflect agreed intent; code/tests are evidence of implementation, not automatic authority to redefine intent.

If actual behavior differs from the approved intent, record the mismatch and ask for a decision. Do not silently rewrite requirements. Link the issue/MR in a change record only when the rationale or decision needs durable context beyond GitLab history.

Do not claim tests passed unless the result is available. Report changed docs, the evidence used, and any unresolved discrepancies.
