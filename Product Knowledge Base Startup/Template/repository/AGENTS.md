# Project guidance

## Product documentation

- Start at [`docs/README.md`](docs/README.md) to find the project knowledge base.
- For a business behavior change, read the relevant files in `docs/business/` before planning or editing.
- For a technical change, read the relevant files in `docs/technical/`.
- Read only the documents relevant to the current task; follow links from the index as needed.
- Treat reviewed business documents as the agreed description of intended behavior. Treat code and tests as evidence of implemented behavior.
- If sources conflict or leave a gap, report it. Do not invent business rules or silently resolve conflicts.
- Update relevant business or technical documents in the same change when the agreed behavior or technical solution changes.
- Cite the source files that support claims in documentation and change records.

Keep these instructions short. Put product facts in `docs/`, not here.
