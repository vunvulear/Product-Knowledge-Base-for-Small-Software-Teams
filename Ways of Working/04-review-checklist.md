# Review checklist

## Business documentation

- [ ] Purpose, requirements, rules, and flows are supported by approved sources.
- [ ] The language is understandable for business readers.
- [ ] Missing intent is recorded as an open question, not guessed.

## Technical documentation

- [ ] Claims describe the current implementation/design and link to evidence.
- [ ] Inferences are labeled; code behavior is not presented as proof of business intent.
- [ ] Only relevant technical docs were changed.

## Change delivery

- [ ] Issue and MR are linked.
- [ ] Acceptance examples and test results are recorded accurately.
- [ ] Current docs match agreed intent and delivered technical solution, or remaining mismatch is explicit.
- [ ] No duplicate bug log or change archive was created without a reason.

## Agent discoverability

- [ ] Index links resolve.
- [ ] Agent guidance points to the index.
- [ ] Relevant docs are linked from the issue/MR when helpful.
