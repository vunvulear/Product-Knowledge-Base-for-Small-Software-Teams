# 00 - Discover the project (read-only)

Review this repository without changing any files. Identify the project root(s), main code areas, tests, configuration, existing Markdown and Word documents (`.doc` / `.docx`), issue/MR templates, and any existing business or technical documentation.

Use only the repository sources. Do not infer business purpose from names alone. Report:

1. A compact project map.
2. Existing sources that describe business purpose, requirements, rules, workflows, architecture, data, integrations, and operations.
3. Important gaps or conflicts, with exact paths and section/page references where available.
4. Which parts of the repository appear to be separate projects and why.
5. A recommended minimal docs structure for this repository.

Do not generate requirements or write files in this pass. If a Word document cannot be read in this environment, state that clearly and name the file.
